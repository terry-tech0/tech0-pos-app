## 1. 背景と目的（要求の出発点）

### 1.1 想定店舗

**架空の小型食品スーパー「あおぞらマート」**（1店舗・個人経営規模）

| 項目 | 設定 |
|---|---|
| 業態 | 食品スーパー（生鮮・加工食品・日用雑貨） |
| 規模 | 売場約100坪、取扱商品約3,000 SKU |
| レジ | 2台（ピーク時のみ2台稼働） |
| 従業員 | 店長1名、パート・アルバイト8名 |
| 営業時間 | 9:00〜21:00 |

### 1.2 店舗が抱える課題（ビジネス要求）

| # | 現状の課題 | 店舗の要求 |
|---|---|---|
| R-1 | 会計は電卓＋手書き併用で、打ち間違い・計算間違いが起きる | **会計の金額計算を正確・自動にしたい** |
| R-2 | 商品の値段をレジ担当が暗記・値札目視で打っており、新人が使えない | **商品コードを入れれば名前と値段が出るようにしたい**（新人でも即戦力化） |
| R-3 | 食品8%・雑貨10%の税率が混在し、手計算では軽減税率の処理を間違える | **税率の区別を自動でやってほしい** |
| R-4 | 何がいつ・いくつ売れたか記録がなく、発注が勘頼み | **売上の記録を残して、あとから見られるようにしたい** |

### 1.3 システム化の目的

上記要求を満たす**レジ会計アプリ（POS）**を段階的に構築する。
Lv2 では「商品マスタ照会 → 購入リスト作成 → 会計金額の自動計算 → 取引記録の保存」までを実現する。

## 2. 業務要件

### 2.1 対象業務の範囲

レジ担当者が行う**会計業務**を対象とする。開店準備・発注・棚卸はスコープ外（将来拡張）。

### 2.2 会計業務フロー（To-Be）

```
[お客様がレジに商品を持ってくる]
        │
        ▼
① レジ担当が商品の商品コードを入力する
        │
        ▼
② 画面に商品名・単価が表示される
   （マスタ未登録なら「商品がマスタ未登録です」と表示 → 店長へ連絡）
        │
        ▼
③ 「追加」で購入リストに載せる（同一商品は数量を増やす）
        │
        ▼
④ 商品ぶんだけ ①〜③ を繰り返す
        │
        ▼
⑤ 「購入」ボタンで合計金額（税込）を確定・表示する
        │
        ▼
⑥ 現金を受け取り、釣り銭を渡す（現金授受はシステム外・手動）
        │
        ▼
⑦ 取引内容（日時・レジ担当・明細・合計）が自動で記録される
```

### 2.3 業務上のルール

| # | ルール |
|---|---|
| B-1 | 税率は商品ごとに決まる：食品＝軽減税率8%、日用雑貨・酒類＝標準税率10% |
| B-2 | 商品マスタの登録・価格改定は店長のみが行う（Lv2ではDB直接メンテで代替） |
| B-3 | 会計途中の取り消し（リストから削除）は認める。**確定後の取消（返品）は Lv2 ではスコープ外** |
| B-4 | 支払いは現金のみを想定（キャッシュレスは将来拡張） |
| B-5 | 取引記録は削除しない（売上分析・監査の元データ） |

### 2.4 利用者

| 利用者 | 役割 | ITリテラシー前提 |
|---|---|---|
| レジ担当（パート・アルバイト） | 会計操作 | 低くてよい（研修10分で使える操作性） |
| 店長 | マスタ管理・売上記録の確認 | 普通 |

## 3. 機能要件（Lv2 スコープ）

### 3.1 機能一覧

| ID | 機能名 | 内容 | 対応要求 |
|---|---|---|---|
| F-01 | 商品コード入力 | 商品コード（13桁想定）を入力できる | R-2 |
| F-02 | 商品マスタ照会 | 入力コードで商品マスタを検索し、商品名・単価を表示する。未登録時はその旨を表示する | R-2 |
| F-03 | 購入リスト追加 | 照会した商品を購入リストに追加する。リストには商品名・単価・数量・金額を表示する | R-1 |
| F-04 | 購入リスト編集 | リスト上の商品の数量変更・行削除ができる | R-1, B-3 |
| F-05 | 合計金額計算 | 購入リストの合計金額（税込）を自動計算する。税率は商品ごとの税率区分（8%/10%）を適用する | R-1, R-3 |
| F-06 | 購入確定 | 「購入」操作で取引を確定し、合計金額（税込・税抜）をポップアップ表示する。確定後リストはクリアされ次の会計に移る | R-1 |
| F-07 | 取引記録保存 | 確定した取引をDBに保存する（取引ヘッダ＋取引明細） | R-4 |

> **講座仕様との整合メモ**：Lv2 の公式仕様が税率10%固定の場合、F-05 の軽減税率対応（8%/10%混在）は Lv3 以降へ後送りし、Lv2 では「税率区分をデータとして持つが計算は10%固定」に読み替える。

### 3.2 画面要件

Lv2 は **レジ画面1画面** で完結させる。

| 画面要素 | 内容 |
|---|---|
| 商品コード入力欄 | 手入力（Lv2ではスキャナなし） |
| 商品情報表示エリア | 商品名・単価（未登録時はエラーメッセージ） |
| 追加ボタン | 表示中の商品を購入リストへ |
| 購入リスト | 商品名 × 数量 × 単価 ＝ 金額 の一覧 |
| 合計表示 | 税込合計（8%/10%内訳が分かること） |
| 購入ボタン | 取引確定 → 合計金額ポップアップ → リストクリア |

### 3.3 データ要件

| テーブル | 主な項目 |
|---|---|
| 商品マスタ | 商品コード、商品名、単価（税抜）、税率区分（8%/10%） |
| 取引 | 取引ID、取引日時、レジ担当コード、店舗コード、POS機ID、合計金額（税込）、税抜合計 |
| 取引明細 | 取引ID、明細番号、商品コード、商品名、単価、数量 |

- 商品マスタの初期データとして、架空の商品30件程度（食品・雑貨混在）を用意する
- 取引・取引明細は追記のみ（B-5）

## 4. 非機能要件（Lv2 相当の簡易版）

| 分類 | 要件 |
|---|---|
| 性能 | 商品照会は入力から1秒以内に表示。会計1件を1分以内に完了できる操作性 |
| 可用性 | 営業時間中に使えること。学習用のためSLA等は定めない |
| セキュリティ | DBの認証情報はコード内に書かずに環境変数で管理する。公開リポジトリに実データ・秘密情報を置かない |
| 操作性 | レジ未経験のアルバイトが10分の説明で使える画面にする（ボタンは大きく、操作は上から下へ一方向） |
| 保守性 | 要件・設計・実装をすべてGitHubで管理し、変更履歴を追えるようにする |

## 6. 前提・制約

- 学習用プロジェクトであり、実在の店舗・実データは扱わない（店名・商品・人物はすべて架空）
- リポジトリは public（https://github.com/terry-tech0/tech0-pos-app ）
- 技術スタックは Lv2 実装フェーズで決定する（講座指定があればそれに従う）

## 7. 用語集

| 用語 | 意味 |
|---|---|
| POS | Point of Sale。販売時点の会計・記録を行う仕組み |
| SKU | Stock Keeping Unit。在庫管理上の最小商品単位 |
| 軽減税率 | 飲食料品等に適用される消費税8%の税率 |
| 取引／取引明細 | 1回の会計＝取引（ヘッダ）、その中の商品行＝明細 |
