## 1. 要求（上位文書からの転記）

講座配布の要求定義書より。**Lv2 ＝ Lv1（初級編）の要求＋追加3項目**。

### 1.1 Lv1 簡易POSアプリ初級編の要求

| ID | 要求 |
|---|---|
| REQ-01 | 自分はレジ担当者で自らのIDを使ってアプリにログインする |
| REQ-02 | 会員カード（識別番号）を読み込む |
| REQ-03 | 商品コードを手入力し追加ボタンで登録する |
| REQ-04 | 合計金額を税抜きと税込で表示する |
| REQ-05 | 購入ボタンで購入できる（決済システムは作らない） |
| REQ-06 | 購入ボタン押下後は商品登録欄を空にし、会員カードの読み込みから再開できる |
| REQ-07 | 購入履歴を保存できる |
| REQ-08 | 税率を可変できる（例：食品の消費税率が来年から変わっても対応できる） |

### 1.2 Lv2 簡易POSアプリ改の追加要求

| ID | 要求 |
|---|---|

| REQ-10 | 読み込んだ商品の削除、数量変更 |
| REQ-11 | 会員特典の割引機能 |

## 2. 業務要件

### 2.1 想定店舗（実店舗は自由選択のため以下を設定）

**架空の小型食品スーパー「あおぞらマート」**（1店舗・個人経営規模）

| 項目 | 設定 |
|---|---|
| 業態 | 食品スーパー（生鮮・加工食品・日用雑貨） |
| 規模 | 売場約100坪、取扱商品約3,000 SKU |
| レジ | 2台（ピーク時のみ2台稼働） |
| 従業員 | 店長1名、パート・アルバイト8名 |
| 営業時間 | 9:00〜21:00 |
| 会員制度 | 無料の店舗会員カードあり。**会員は割引特典**（§2.4）を受けられる |

スーパーを選んだ理由：POSの王道で業務を具体化しやすく、**食品8%・雑貨10%の税率混在**が REQ-08（税率可変）を現実の業務要件として深掘りする教材になるため。

### 2.2 対象業務と利用者

レジ担当者が行う**会計業務**を対象とする。発注・棚卸・マスタ登録業務はシステム化の対象外（マスタはDB直接メンテで代替）。

| 利用者 | 役割 | 前提 |
|---|---|---|
| レジ担当（パート・アルバイト） | ログインして会計操作 | ITリテラシーは低くてよい（研修10分で使える操作性） |
| 店長 | 商品・会員・税率マスタの管理、購入履歴の確認 | 普通 |

### 2.3 会計業務フロー（To-Be）

```
（勤務開始時）
⓪ レジ担当が自分のIDでアプリにログインする            … REQ-01
        │
（お客様1人ごと）
① 会員カードを読み込む（非会員なら「会員なし」で開始）   … REQ-02
        ▼
② 商品のバーコードを読み込む                          … REQ-09
   → 商品名・単価・数量が表示され、リストに載る
   （バーコードが読めない商品は商品コードを手入力＋追加ボタン … REQ-03）
   （マスタ未登録なら「商品がマスタ未登録です」と表示 → 店長へ連絡）
        ▼
③ 必要に応じてリストを編集する                        … REQ-10
   （数量変更・行削除。お客様の「やっぱりやめる」に対応）
        ▼
④ 合計金額が税抜き・税込の両方で表示される             … REQ-04
   （会員の場合は割引適用後の金額 … REQ-11）
        ▼
⑤ 「購入」ボタンで確定する（決済システムは作らない。     … REQ-05
   現金授受・釣り銭はシステム外・手動）
        ▼
⑥ 購入履歴（日時・担当・会員・明細・金額）が保存される    … REQ-07
        ▼
⑦ 商品登録欄が空になり、次のお客様の                   … REQ-06
   会員カード読み込みから再開できる
```

### 2.4 業務ルール

| # | ルール | 関連要求 |
|---|---|---|
| B-1 | 消費税率は商品ごとの税率区分で決まる：食品＝軽減税率8%、日用雑貨・酒類＝標準税率10% | REQ-04, 08 |
| B-2 | **税率は法改正で変わりうる**（例：食品8%→1%）。税率の値は税率マスタで管理し、プログラム修正なしで店長が変更できる状態を要件とする | REQ-08 |
| B-3 | 会員特典：**会員は税抜合計から5%割引**。割引後の金額に消費税を課す。非会員は割引なし | REQ-11 |
| B-4 | 会計途中の削除・数量変更は認める。**購入確定後の取消（返品）はスコープ外** | REQ-10 |
| B-5 | 支払いは現金のみを想定（決済システムは作らない） | REQ-05 |
| B-6 | 購入履歴は削除しない（売上確認・監査の元データ） | REQ-07 |
| B-7 | 商品・会員・税率マスタの登録・変更は店長のみ（Lv2ではDB直接メンテで代替し、管理画面は作らない） | — |

## 3. 機能要件

### 3.1 機能一覧（要求トレーサビリティ）

| ID | 機能名 | 内容 | 対応要求 |
|---|---|---|---|
| F-01 | レジ担当ログイン | レジ担当IDとパスワードでログインする。ログイン中の担当IDを取引に記録する | REQ-01 |
| F-02 | 会員カード読み込み | 会員識別番号を読み込み、会員を特定する。非会員として開始することもできる | REQ-02 |
| F-03 | バーコード読み込み | 商品バーコード（JAN13桁想定）を読み込み、商品マスタを照会して商品名・単価・数量を表示し、購入リストへ追加する。同一商品の再読込は数量+1 | REQ-09 |
| F-04 | 商品コード手入力 | 商品コードを手入力し「追加」ボタンで購入リストへ登録する（バーコード不良時の代替経路） | REQ-03 |
| F-05 | 未登録商品エラー表示 | マスタ未登録コードの場合「商品がマスタ未登録です」と表示し、リストに追加しない | REQ-03, 09 |
| F-06 | 購入リスト編集 | リスト行の数量変更・行削除ができる | REQ-10 |
| F-07 | 会員割引適用 | 会員の場合、税抜合計に5%割引を適用する。割引額を画面に表示する | REQ-11 |
| F-08 | 合計金額表示 | 合計金額を**税抜き・税込の両方**で常時表示する。税率は商品ごとの税率区分×税率マスタの現在値で計算する（8%/10%の内訳表示） | REQ-04, 08 |
| F-09 | 購入確定 | 「購入」ボタンで取引を確定し、合計（税抜・税込）を表示する。決済処理は行わない | REQ-05 |
| F-10 | 購入履歴保存 | 確定した取引を購入履歴（取引ヘッダ＋明細）としてDBに保存する | REQ-07 |
| F-11 | 会計リセット | 購入確定後、商品登録欄・購入リストを空にし、次の会員カード読み込みから再開できる | REQ-06 |
| F-12 | 税率可変 | 税率マスタ（税率区分ごとの税率値）を変更すれば、以後の会計に新税率が適用される。過去の購入履歴は購入時点の税率で保持される | REQ-08 |

※ 全要求 REQ-01〜11 が F-01〜12 のいずれかに対応（漏れなし）。＋αの機能は追加しない。

### 3.2 画面要件

Lv2 は **ログイン画面＋レジ画面** の2画面で構成する。

**ログイン画面**：レジ担当ID・パスワード入力、ログインボタン。

**レジ画面**（上から下へ業務フロー順に配置）：

| 画面要素 | 内容 |
|---|---|
| 会員カード読み込み欄 | 会員識別番号の入力（読み込み後、会員名と「割引対象」を表示）。「会員なし」ボタンあり |
| バーコード読み込み欄／商品コード入力欄＋追加ボタン | 読み込み・入力した商品の商品名・単価を表示 |
| 購入リスト | 商品名 × 数量 × 単価 ＝ 金額。行ごとに数量変更・削除操作 |
| 合計表示 | 税抜合計・割引額・税込合計（税率8%/10%の内訳つき） |
| 購入ボタン | 確定 → 合計表示 → リストと会員情報をクリア |

操作性の方針：レジ未経験のアルバイトが10分の説明で使える（ボタンは大きく、操作は上から下へ一方向）。

### 3.3 データ要件

| テーブル | 主な項目 | 関連 |
|---|---|---|
| レジ担当マスタ | 担当ID、氏名、パスワード（ハッシュ化） | F-01 |
| 会員マスタ | 会員識別番号、氏名、割引区分 | F-02, 07 |
| 商品マスタ | 商品コード（JAN）、商品名、単価（税抜）、税率区分 | F-03〜05 |
| 税率マスタ | 税率区分（標準/軽減）、税率値、適用開始日 | F-08, 12 |
| 購入履歴（取引） | 取引ID、取引日時、レジ担当ID、会員識別番号（非会員はNULL）、税抜合計、割引額、税込合計、適用税率 | F-10 |
| 購入履歴（明細） | 取引ID、明細番号、商品コード、商品名、単価、数量、税率区分、適用税率 | F-10 |

- 明細に商品名・単価・適用税率を**転記して保存**する（マスタが後で変わっても履歴が購入時点の事実を保持する。B-6, F-12）
- 商品マスタの初期データとして架空の商品30件程度（食品・雑貨混在）を用意する

## 4. 非機能要件

Week2 宿題で名指しされた**セキュリティ・運用**を中心に定義する。

### 4.1 セキュリティ

| ID | 要件 |
|---|---|
| NFR-SEC-01 | レジ担当はID・パスワードによる認証なしにアプリを利用できないこと（REQ-01） |
| NFR-SEC-02 | パスワードは平文で保存しないこと（ハッシュ化） |
| NFR-SEC-03 | DB接続情報・秘密鍵はコードに書かず環境変数で管理し、公開リポジトリにコミットしないこと |
| NFR-SEC-04 | 金額計算（合計・割引・税額）はバックエンドで行い、フロントエンドから送信された金額をそのまま信用しないこと |
| NFR-SEC-05 | 入力値（商品コード・会員番号等）はバックエンドで検証すること（SQLインジェクション対策を含む） |
| NFR-SEC-06 | 会員情報・購入履歴は業務上必要な範囲でのみ表示し、実在の個人情報は扱わない（学習用の架空データのみ） |

### 4.2 運用

| ID | 要件 |
|---|---|
| NFR-OPS-01 | 営業時間（9:00〜21:00）中に利用できること。学習用のためSLAは定めない |
| NFR-OPS-02 | システム障害時は手動レジ（電卓＋手書き控え）で業務を継続し、復旧後に取引を後入力する運用とする（アプリ側の機能は作らない） |
| NFR-OPS-03 | マスタ（商品・会員・税率・担当）の変更は店長が営業時間外に行う運用とする |
| NFR-OPS-04 | 税率改定時は、税率マスタの変更のみで対応できること（プログラム修正・再デプロイを要しない。REQ-08） |
| NFR-OPS-05 | 購入履歴は追記のみとし、削除・改変の操作を提供しないこと |

### 4.3 性能・その他

| ID | 要件 |
|---|---|
| NFR-PERF-01 | バーコード読み込み・商品照会は1秒以内を目安に表示すること |
| NFR-PERF-02 | 会計1件（読み込み〜購入確定）を1分以内に完了できる操作性とすること |
| NFR-MNT-01 | 要件・設計・実装・テストを GitHub で管理し、変更履歴を追えること |

## 6. 前提・制約

- 学習用プロジェクトであり、実在の店舗・実データは扱わない（店名・商品・人物・会員はすべて架空）
- リポジトリは public（https://github.com/terry-tech0/tech0-pos-app ）で12期全体に共有する（Week5 の指定を先取り）
- バーコードの読み取り方式（ハードウェアスキャナ／カメラ／手入力シミュレート）は Week3 の設計仕様書で決定する
- 技術スタック・アーキテクチャ（Azure デプロイ前提、Vercel/Streamlit 禁止）は Week3 以降の設計フェーズで決定する

## 10. 生成AI活用の記録

本書は **Claude Code（Claude Fable 5）との対話で作成**した。課題要件「生成AIを使った部分を記載」への対応。

### 進め方（人間が意思決定し、AIを構造化・検証に使う）

1. 人間：プロジェクト方針（3ヶ月・GitHub管理・public）と題材の選定基準を提示
2. AI：題材（スーパー）と理由（税率混在が要求REQ-08の教材になる）を提案 → 人間が承認
3. AI：公式要求 未入手のまま初版を仮置きし、**仮定であることを§8に明示**
4. 人間：Slackスレッドの情報（要求定義書＝MindMeister）を提供
5. AI：ブラウザでMindMeisterの要求定義書を読み取り、要求11項目を転記
6. AI：初版との差分を洗い出し（初版はログイン・会員・バーコードが欠落、バーコードを誤ってスコープ外に置いていた）→ v0.2 へ全面改訂
7. 人間：会員割引の内容（5%）等、要求が具体を定めていない箇所の裁定（最終確認はこれから）

### うまくいったこと・学び

- AIに公式要求へのアクセス手段（ブラウザ）を渡したことで、「AIの推測で書いた要件」を「要求から落とした要件」に置き換えられた。**要求の実物を読ませる前のAI出力は、もっともらしいが要求と食い違う**（初版のバーコード誤配置が実例）
- 要求→機能のトレーサビリティ表をAIに作らせると、要求の取りこぼしチェックが機械的にできる
